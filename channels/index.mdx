<Info>
  Channels are the **surfaces** your Qor uses to reach users. Telegram, WhatsApp, Slack DM, Discord DM, email, SMS — each is a channel. Qorven supports 20+ out of the box, with consistent setup and a shared [unified-chat](/channels/unified-chat) model.
</Info>

## Channel families

Qorven treats channels differently based on family:

<CardGroup cols={2}>
  <Card title="Chat-family (merges into canonical chat)" icon="infinity">
    web, tui, webchat, telegram, whatsapp, slack DM, discord DM, teams, line, signal, imessage, facebook, matrix, mattermost, feishu, dingtalk, wecom, zalo.

    Every message lands in the Qor's single canonical chat, tagged by channel. The web/TUI sees everything; each channel sees only its own slice.

    [Unified chat model →](/channels/unified-chat)
  </Card>
  <Card title="Non-chat (own sessions)" icon="folder">
    email, sms, github, webhook.

    These are genuinely different mediums — email has threads and subject lines, GitHub has issues and PRs, webhooks can be any shape. They get their own sessions and their own rendering.
  </Card>
</CardGroup>

## Setup at a glance

The setup flow is the same for every channel:

<Steps>
  <Step title="Get credentials from the provider">
    Telegram needs a bot token from `@BotFather`. WhatsApp needs a Meta app. Slack needs an OAuth app. Email needs IMAP + SMTP credentials. Per-channel pages walk you through each.
  </Step>
  <Step title="Add the channel in the UI">
    **Settings → Channels → Add channel**. Pick the provider, paste credentials. Qorven encrypts them immediately.
  </Step>
  <Step title="Point the webhook at Qorven">
    For providers that push events, set the webhook URL to `https://your-qorven/v1/webhooks/<channel>`. Use Cloudflare Tunnel or ngrok for dev.
  </Step>
  <Step title="Bind a Qor">
    One channel → one Qor. That Qor handles inbound; it can delegate.
  </Step>
  <Step title="Send a test message">
    Message from the channel. Watch it appear in the web UI canonical chat. Done.
  </Step>
</Steps>
